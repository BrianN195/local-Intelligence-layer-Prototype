# API Routes

This document records a proposed route inventory and the behavior associated with each route. It is a specification, not confirmation that these endpoints or features are implemented in the current codebase. Verify each route against the running application and source before treating it as available.

> **Current implementation note:** The routes in this proposal are not mounted by the current Local Intelligence app unless independently verified in its source. Session, Media, Simulator, Analytics, and Recovery routes below are design proposals; their MongoDB-backed behavior is not implemented by the current run-snapshot persistence layer.

> The endpoint strings below are preserved exactly as supplied. In particular, `PATCH//experiments/:id/complete` and `GET//experiments/:id/export` contain doubled slashes in the source; whether those slashes are intentional is uncertain and should be verified.

## Experiments

- `POST /experiments` — Creates an experiment run, initializes its lifecycle, links it to a session, and sets the experiment status to running.
- `PATCH//experiments/:id/complete` — Completes an experiment run, records the end time, updates the final status, summary, and result, and logs a protocol event.
- `GET /experiments/:id/summary` — Returns a statistical summary of an experiment, including participants, signals, propagation events, observations, warnings, failures, and collective behavior results.
- `GET//experiments/:id/export` — Exports experiment-related data, including agents, participants, signals, propagation events, observations, protocol events, warnings, failures, and analysis results.
- `GET /experiments/:id/timeline` — Returns the chronological sequence of protocol events recorded during an experiment.

## Agents and neighborhoods

- `POST /agents` — Registers a mobile device as an agent, creates its initial state, and marks the agent as online.
- `PATCH /agents/:id/state` — Updates an agent's current state, stores the transition in the history, and records the change as a protocol event.
- `POST /neighborhoods` — Creates a neighborhood for an experiment and assigns the selected agents to it.

## Signals and propagation

- `POST /signals` — Creates a signal generated by an agent, assigns a correlation ID, and logs the signal creation.
- `PATCH /signals/:id/status` — Updates a signal's processing status and records the status change in the protocol log.
- `POST /propagation` — Creates a propagation event representing the transmission of a signal between two agents and records the event.
- `PATCH /propagation/:id/status` — Updates a propagation event's status (for example, sent, received, processed, or failed) and records the transition.

## Diagnostics and authentication

- `GET /diagnostics` — Provides an overview of current system health, including agent status, running experiments, and recent activity during the last 30 minutes.
- `GET /experiments/:id/diagnostics` — Returns diagnostic information for a specific experiment, including statistics, warnings, failures, recent protocol events, and behavior-analysis results.
- `POST /auth` — Authenticates the controller using a password, applies rate limiting to failed attempts, and returns a JWT valid for 24 hours.

## Analytics

- `GET /analytics/events` — Returns the latest persistent protocol events from the database, with an optional `limit` parameter controlling the number of returned events.
- `GET /analytics/summary` — Returns an analytics summary for a specified time range, including the total number of protocol events and their distribution by event type and namespace.

## Rule sets

- `POST /rulesets` — Creates a `RuleSet` for an existing experiment, stores its rules and configuration, and records its creation as a protocol event.
- `PATCH /rulesets/:id/assign` — Assigns an existing `RuleSet` to an experiment, makes it the experiment's active `RuleSet`, activates the `RuleSet`, and records the assignment as a protocol event.

## Sessions

- `POST /sessions` — Creates a session for a connected client or performer, stores its socket and performer information, and records its creation as a protocol event.
- `GET /sessions/:id` — Returns a session by its ID, including its connection status and associated information.
- `PATCH /sessions/:id/disconnect` — Disconnects a session, stores the disconnection reason and last-seen time, and records the disconnection as a protocol event.
- `PATCH /sessions/:id/connect` — Reconnects a session, clears the previous disconnection reason, updates the last-seen time, and records the reconnection as a protocol event.

## Simulator

- `GET /simulator/scenarios` — Returns the available simulator scenarios that can be selected for a run.
- `GET /simulator/runs` — Returns a list of simulator runs that have been created or executed.
- `DELETE /simulator/reports` — Deletes or clears generated simulator reports and returns the cleanup result.
- `POST /simulator/runs` — Starts a simulator run for a selected scenario and returns the newly created run.
- `GET /simulator/runs/:runId` — Returns the current information and status of a specific simulator run.
- `GET /simulator/runs/:runId/report` — Returns the generated report for a completed simulator run by reading the Markdown report and rendering it as an HTML document.

## Media

- `GET /visuals` — Returns the available visual media files and parsed metadata, using MongoDB data when available and falling back to the `public/visuals` directory.
- `GET /sounds` — Returns the available sound files and parsed metadata, using MongoDB data when available and falling back to the `public/sounds` directory.
- `GET /mp3s` — Returns the available MP3 files and parsed metadata, using MongoDB data when available and falling back to the `public/mp3s` directory.

## Recovery

- `GET /recovery/database` — Returns the current MongoDB load, including database statistics, collection count, storage usage, and document counts for sessions, states, and media.
- `DELETE /recovery/database/sessions` — Deletes disconnected sessions from the database and returns the number deleted together with the updated database load.
